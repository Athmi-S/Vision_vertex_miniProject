Voice Accessibility Flow

QUESTION PHASE TTS reads: "Question 1 of 6. [question text]. Option 1: [text]. Option 2: [text]... Say your answer now." ↓ (TTS finishes) 🎤 Mic opens automatically User says: "two" / "option 2" / "second" ↓ TTS says: "Selecting Option 2: [text]. Submitting." ↓ (answer submitted to backend) FEEDBACK PHASE TTS says: "Correct! Explanation: [text]. Shall we move to the next question? Say yes to continue, or no to stay." ↓ (TTS finishes) 🎤 Mic opens automatically User says: "yes" ↓ TTS says: "Moving to the next question." ↓ Next question loads → cycle repeats LAST QUESTION TTS asks: "Shall we finish the assessment? Say yes to view results." User says: "yes" → Results page loads

Key Technical Notes

Security
  • Passwords stored as bcrypt hashes — never plaintext
  • JWT in HttpOnly cookie — not accessible to JavaScript
  • learner_id always taken from authenticated cookie — never from request body
  • is_correct on options never returned before the learner submits
  • Secrets stored in .env file — gitignored
Accessibility
  • Semantic HTML — landmarks, headings, skip links on every page
  • All interactive elements keyboard-navigable (Tab / Enter / Space)
  • role="alert" on errors, aria-live on status messages
  • TTS auto-reads questions + feedback — no manual button press needed
  • STT mic auto-opens after TTS finishes — fully hands-free assessment
  • Screen-reader compatible labels on all buttons and form fields
Known Constraints
  • STT works in Chrome and Edge only (Web Speech API limitation)
  • bcrypt must stay pinned to ==4.2.1 — bcrypt 5.x incompatible with passlib 1.7.4
  • All question text is plain ASCII — Windows cp1252 terminal constraint
  • Run backend with .\venv\Scripts\python.exe -m uvicorn not plain uvicorn
